# Content Library C2a contract and implementation report

Inspected migrations, Creator/Admin middleware, immutable Template versions and review references, custom exercise schemas/fixtures, learning configuration and GeoNames catalogs before extending the API.

Contract differences: the supplied BE checkout has 15 Personal and seven canonical Team mechanics, schemaVersion 1. Exercise classification means personal/team; library category is separate. Existing exercise id/owner are Template-version identities and MUST be omitted for library saves. Library contentId/revisionId/ownerId live in the response envelope. The exact exercise object is retained without normalization, including LaTeX, whitespace, interaction, answers, hints, feedback and solution. Validation reuses the existing bounded canonical validator. Navigation has no canonical contract and is rejected. Verified FE main files content/catalog.ts, content/classification.ts, exercises/persistenceAdapter.ts, exercises/persistenceSchema.ts and docs/Creator_Content_Library_C1.md through the GitHub connector. FE toPersistence/fromPersistence already provides the canonical schemaVersion 1 conversion; no second editor schema is needed. FE ContentRecord.category is a UI section (Personal Challenges/Team Challenges/Navigation Hints), mapped from exercise.classification; BE category maps to FE activityCategory. FE geography currently holds display strings; resolve them through the existing catalog before saving canonical codes/IDs. FE curriculum is an association array with grade number and Main display labels; C2a uses an optional partial classification object with string grade and subject math. Do not send the UI association array or infer official Main IDs. Backend lifecycle draft/submitted/changes_requested differs from UI unreviewed/pending/rejected and requires explicit display mapping; repository revision locators are never backend revision IDs. Collections/provenance are C2 dependencies, not fabricated records.

POST /api/creator/content accepts {exercise, category?, curriculum?, geography?}. PUT /api/creator/content/:id accepts the same full replacement plus required baseRevisionId. Each save appends an immutable revision with a fresh UUID and monotonically increasing version. POST /:id/revisions accepts {baseRevisionId} and clones the exact current revision as a new draft, including from approved/submitted/changes_requested. PUT is draft-only. Approved revisions remain immutable. GET /:id returns the owner's current revision; GET /:id/revisions/:revisionId retrieves an exact owner revision. GET / lists own draft heads with limit (default 50, max 100) and after (UUID keyset). Response is {contentId, ownerId, createdAt, updatedAt, revisionId, version, status, exercise, category, curriculum, geography}; lists use {items,nextAfter}. Stale saves return 409. Other owners get 404. Only active non-guest Creators may access; Admin alone has no implicit Creator permission.

Category is optional and uses the existing FE activity category vocabulary Mathematics/History/Science/Mixed; All is a filter only. Curriculum accepts only FE grade values 5–12 and subject math (both optional); Main/Unit/Lesson require an agreed canonical catalog and are rejected for now. Curriculum is JSONB for future subject-specific schemas. Missing classifications are valid drafts. Geography defaults to {scope:universal}; explicit country uses countryCode, region adds admin1Code, city uses countryCode and geographicId (GeoNames decimal string). Foreign keys reference existing catalogs. No labels are interpreted as identifiers. Universal applicability is inclusive in future local selection; allocation/filtering is outside C2a.

All revisions are immutable at the DB level except lifecycle status transitions; non-draft statuses cannot return to draft. Approval will reference an exact revisionId; no approval API is added. Archived heads can be read but cannot be revised. History is independent of Templates/Hunts, which are neither migrated nor edited. Owner FK restricts deletion to preserve provenance. New schema is additive migration 042. No import, gameplay, selection, publication, approval UI or deployment.
